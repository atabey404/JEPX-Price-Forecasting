# JEPX 第二阶段第4步：主表与简单基线

已形成第一版研究主表，并完成四种预先确定的价格基线逐日复算。未训练机器学习价格模型，未验证天气增益，也没有生成当前日期的实盘预测。

## 本次范围

使用2026-11-05留存的三个数据包，不重新下载或改写原始历史。

- 主表：2026-04-04—2026-11-06，共217天、东京/关西/九州3个区域、每天48个半小时时段，共31,248行。
- 每区域保留3个气象点，共21个气象变量，点的对应关系见`docs/data_contract.json`。
- 价格基线另评价System Price。系统价格只统计一次，未把三区重复的系统价格当作三份样本。
- 开发段：2026-04-04—2026-06-30，共88天。
- 后段评估：2026-07-01—2026-11-06，共129天，每个价格目标6,192个时段。
- 所有结果均为当前依据留存历史数据进行的事后复算，不是当时实际签发并留档的预测。

## 四个简单基线

| 文件中的方法名 | 计算规则 |
|---|---|
| previous_day | 前一天同一半小时时段价格 |
| previous_week | 7天前同一半小时时段价格 |
| four_week_same_slot_mean | 7、14、21、28天前同一时段价格的均值 |
| seven_day_same_slot_median | 前1至7天同一时段价格的中位数 |

每个目标日仅使用此前交付日已出清的日前价格。各方法不拟合参数，逐日更新历史输入。四种方法在计算结果前已固定；不根据后段结果调参或挑选单一方法部署。后段内较晚日期允许使用前一天已知的出清价格，这属于逐日更新，不是一次性预测整个后段。

MAE、RMSE、偏差、绝对误差中位数均为JPY/kWh。价格可能接近零，本版不使用MAPE。不同方法的比较使用完全相同的日期和时段。

## 时点与气象对齐

竞价截止：交付日前一天10:00 JST。

价格输入为此前交付日的日前出清价格。以“相应交付日前一天12:00 JST已经可用”为保守研究假设，所有价格滞后输入均早于目标截止；未重建历史修订版本和实际首次发布时间，不能据此声称对全部历史版本完全无泄漏。

气象按同一个已选定的GFS批次对齐：

- 气温、湿度、10/100米风速、云量：整点取原值；半点在相邻整点之间线性插值。
- 小时平均短波辐射：取下一整点标记、实际对应当前小时区间的原始值，作为该小时两个半小时的共同特征。
- 小时降水总量：同样按其结束时刻对齐，保留为小时总量特征；不是半小时降水量，不能将两行相加当作小时降水。
- 保留原始60分钟分辨率含义；插值得到的特征不宣称为原生30分钟气象。
- 保留12小时计算/发布延迟假设、批次初始化时刻、估算可用时刻、回退天数。`strict_availability_verified`仍为false。
- 不使用ERA5、目标日供需/发电实际、目标日成交量或目标日价格作为特征。
- 日历包含星期、周末、月份和时段周期编码；本版尚未加入权威日本节假日表，不把未知节假日默认为0。

## 运行

依赖：Python 3.11+，pandas 2.2+、numpy、matplotlib。

将前三步数据包解压到同一个父目录，保留各自顶层文件夹；把`JEPX_Step4`放在该父目录，执行：

```sh
python -m pip install -r JEPX_Step4/requirements.txt
python JEPX_Step4/scripts/run_stage4.py
python JEPX_Step4/scripts/verify_outputs.py
```

也可以明确指定前三步解压目录：

```sh
python JEPX_Step4/scripts/run_stage4.py --input-root /path/to/extracted_archives
```

核心运行只读取价格表和固定批次气象表。第二步的实际供需数据保留作后续研究，本版不作为预测输入。

## 校验与下一步

主表无重复键、无空值，每个区域每日48行。已验证：修改目标日及以后价格不会改变该日价格预测特征；气象估算可用时间早于截止；独立复算指标；抽查气象插值与小时结束标记。

本版可用于带明确时点假设的研究回测。下一步在固定评估方案下逐步加入节假日与轻量模型，比较“价格+日历”与“价格+日历+天气”的增量效果；在效果得到验证前，不宣称天气模型优于简单基线。仍需补齐竞价前可用的负荷、风光、备用率等信息，第二阶段全部数据收集尚未结束。
